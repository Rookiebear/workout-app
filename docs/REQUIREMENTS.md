# 筋トレメニュー管理アプリ 要件定義書

2026-11-26 · Ruki Kumasaka

## 概要

トレーニング歴2年未満の個人が、目的に合った根拠のあるメニューを自動で受け取り、記録し、重量を伸ばしていくためのWebアプリ。iPhoneのSafariから開き、ホーム画面に追加して使う。

- 利用者：本人1名（ログイン機能なし）
- 配布：GitHubリポジトリで管理し、GitHub Pagesで公開
- データ：iPhone内に保存し、JSONで書き出し・読み込み
- 単位：kg
- 本書の数値（回数・セット数・休憩・重量の増減幅）は一般的な推奨値を初期値としたもの。すべて設定画面で変更できる前提とする

## 利用環境と種目マスタ

施設にはパワーラックとケーブルマシンがないため、バーベル種目はすべてスミスマシンで置き換える。使える器具は設定でON/OFFでき、OFFの器具を使う種目は生成対象外になる。

| 器具ID | 器具 | 初期状態 | 重量の刻み（初期値） |
| --- | --- | --- | --- |
| smith | スミスマシン | ON | 2.5kg（バー重量は設定で入力） |
| dumbbell | ダンベル | ON | 片手2kg、最大重量を設定 |
| bench | アジャスタブルベンチ | ON | — |
| machine_upper | 上半身マシン | ON | マシンごとに設定（初期5kg） |
| machine_lower | 下半身マシン | ON | マシンごとに設定（初期5kg） |
| bodyweight | 自重 | ON | — |
| cable | ケーブル | OFF | — |

種目マスタはリポジトリ内のJSON（`data/exercises.json`）で持ち、アプリ内でも種目を追加・編集できる。1種目の項目は次のとおり。

| 項目 | 型 | 説明 |
| --- | --- | --- |
| id | string | 例 `smith_bench_press` |
| name | string | 表示名（日本語） |
| equipment | string[] | 必要な器具ID |
| pattern | string | 動作パターン：horizontal_push / vertical_push / horizontal_pull / vertical_pull / squat / hinge / lunge / isolation |
| type | string | compound（多関節）/ isolation（単関節） |
| muscles | {muscle: number} | 部位ごとのセット換算係数。主働筋1.0、補助筋0.5 |
| jointStress | {joint: 0-3} | 関節負担：shoulder / elbow / wrist / lower_back / knee / hip / neck |
| isMainLift | boolean | 筋力モードのメイン種目候補か |
| increment | number | 重量の刻み（kg）。未設定なら器具の初期値 |

部位（muscle）は次の12個を使う：胸・背中（広背筋）・背中（僧帽筋・菱形筋）・肩前部・肩側部・肩後部・上腕二頭筋・上腕三頭筋・大腿四頭筋・ハムストリングス・臀部・ふくらはぎ。腹筋は任意追加。

初期マスタに入れる種目例（各部位に最低3種目、合計40種目程度を目安にする）：

- 胸：スミスベンチプレス、スミスインクラインプレス、ダンベルプレス、チェストプレスマシン、ペックフライマシン
- 背中：ラットプルダウンマシン、シーテッドロウマシン、ワンハンドダンベルロウ、スミスベントオーバーロウ、インクラインダンベルロウ
- 肩：スミスショルダープレス、ダンベルショルダープレス、サイドレイズ、リアデルトマシン、リアレイズ
- 腕：ダンベルカール、インクラインカール、ハンマーカール、スカルクラッシャー（ダンベル）、オーバーヘッドエクステンション（ダンベル）
- 脚：スミススクワット、レッグプレス、スミスルーマニアンデッドリフト、ブルガリアンスプリットスクワット、レッグエクステンション、レッグカール、スミスヒップスラスト、カーフレイズ

施設に実際にあるマシンの種類は未確認。初回起動時に「使えるマシン」をチェックする画面を設ける。

## 目的モード

モードは「筋肥大」「筋力」「減量」の3つで、いつでも切り替えられる。切り替えても履歴と推定1RMは引き継ぎ、次回の重量は新しい回数範囲に合わせて推定1RMから計算し直す。

| パラメータ | 筋肥大 | 筋力 | 減量 |
| --- | --- | --- | --- |
| メイン種目の回数 | 6–10回 | 3–6回 | 6–10回 |
| 補助・単関節種目の回数 | 10–15回 | 8–12回 | 10–15回 |
| 目標RIR（残り回数） | 1–2 | 2–3 | 2–3 |
| 部位あたり週セット数 | 10–16 | 6–10（メイン種目を優先） | 6–10 |
| 種目あたりセット数 | 3 | メイン4・補助3 | 2–3 |
| 休憩（多関節） | 2–3分 | 3–4分 | 2分 |
| 休憩（単関節） | 90秒 | 2分 | 60–90秒 |
| 方針 | ボリュームを確保しながら回数→重量の順に伸ばす | メイン種目の重量を最優先 | 重量を落とさず維持、セット数は筋肥大の約2/3 |

- 筋力モードのメイン種目は `isMainLift: true` の種目から選ぶ（初期値：スミススクワット、スミスベンチプレス、スミスルーマニアンデッドリフト、スミスショルダープレス）
- 減量モードでは体重の記録を促す表示を出す
- 表の値はすべてモード別に設定画面で上書きできる

## メニュー自動生成

週の日数と曜日は自由に設定でき、アプリは「各部位を週≥2回刺激し、モードの週セット数を満たす」ように分割法と種目を決める。生成後は種目の差し替え・追加・削除を手動で行える。

入力：モード、週の日数（1–6）と曜日、その日の持ち時間（分・日ごとに入力）、使える器具、除外リスト、お気に入り、痛みの記録。

分割法の初期割り当て（設定で変更可）：

| 週の日数 | 分割法 | 各部位の頻度 |
| --- | --- | --- |
| 1 | 全身 | 週1回（維持目的と表示） |
| 2 | 全身 A / B | 週2回 |
| 3 | 全身 A / B / C | 週3回 |
| 4 | 上半身 / 下半身 ×2 | 週2回 |
| 5 | 上半身 / 下半身 / プッシュ / プル / 脚 | 週2回 |
| 6 | プッシュ / プル / 脚 ×2 | 週2回 |

生成の手順：

1. 器具OFF・除外リスト・痛みで「強」に該当する種目を候補から外す
2. 部位ごとの週セット数目標を、その部位を扱う日に均等に割り振る
3. 各日、多関節種目→単関節種目の順に選ぶ。同じ動作パターンは1日1種目まで
4. 候補の中では「お気に入り」を優先し、次に前回と同じ種目を優先する（漸進性を追いやすくするため、種目は4–8週は固定）
5. 所要時間を見積もる：ウォームアップ8分＋各セット（作業40秒＋休憩）＋種目切替2分。各メイン種目にはウォームアップセット2〜3本を自動追加
6. 持ち時間を超える場合は、単関節種目のセット→単関節種目そのもの→多関節種目のセットの順に削る。削った分は週内の他の日に回せる場合は回す
7. 週の部位別セット数を集計し、目標の下限を下回る部位を警告表示する

お気に入り・除外：

- お気に入り：種目ごとに☆。生成で優先される
- 除外：種目単位と動作パターン単位で指定でき、期限なし／期限付きを選べる
- 差し替え：種目をタップすると同じ動作パターン・主働筋の候補を一覧表示する

## 重量の提案（漸進性過負荷）

次回の重量・回数はダブルプログレッションで自動提案する。「回数を上限まで伸ばす→重量を上げて回数を下限に戻す」を繰り返す。

判定ルール（種目ごと、前回の本番セットを見る）：

| 前回の結果 | 次回の提案 |
| --- | --- |
| 全セットが回数の上限に届いた | 重量を increment 分上げ、回数は下限から |
| 範囲内だが上限未達 | 同じ重量で各セット+1回を目標に |
| 1セットでも下限を下回った | 同じ重量で再挑戦 |
| 2回連続で下限を下回った | 重量を約10%下げる（刻みに丸める） |
| 3回連続で伸びなし | 種目の差し替えかデロードを提案 |

- RIRは任意入力。入力されていて「上限到達かつRIRが目標+2以上」なら、2刻み分上げる
- 重量は種目の increment、ダンベルは手持ちの重量リストに丸める
- 推定1RMはEpley式で計算し、グラフとモード切替時の重量換算に使う

```
1RM = w × (1 + r / 30)
```

（w：重量、r：回数。rは10回以下のセットのみ使う）

デロード：6週ごと、または「伸びなし」の種目が全体の3分の1を超えたら提案する。1週間、セット数を50%、重量を90%にする。受けるかどうかは本人が決める。

初期重量：

- 分かる種目は「重量×回数」を手入力し、推定1RMからモードの回数範囲に換算する
- 分からない種目は「探り」扱いにする。初回は軽い重量から少しずつ上げ、「あと2〜3回できる」重量で止めて記録。その記録を起点にする

ブランク復帰（その種目の最終実施日からの経過で自動判定）：

| 空白期間 | 重量 | セット数 | 戻し方 |
| --- | --- | --- | --- |
| 2週未満 | そのまま | そのまま | 通常どおり |
| 2–4週 | 90% | 80% | 1回実施したら通常に戻す |
| 1–3か月 | 80% | 70% | 2週間かけて段階的に戻す |
| 3か月以上 | 「探り」扱い | 60% | 新規種目と同じく記録を取り直す |

全体の空白（最後のトレーニングから2週以上）がある場合は、起動時に「復帰プランを使いますか」と確認する。

## 痛みによる回避

痛みのある関節と強さを入力すると、種目の `jointStress` を見て、強さごとに置換・軽量化・除外を自動で行う。

対象の関節：肩・肘・手首・腰・膝・股関節・首（左右の区別も記録するが、判定は左右共通）。

| 強さ | 目安 | アプリの動き |
| --- | --- | --- |
| 軽い | 動かすと少し気になる | その関節の負担が2以上の種目を、同じ主働筋で負担が低い種目に置換。置換できない種目は重量80%・RIR+1 |
| 中程度 | 特定の動きで痛む | 負担が2以上の種目を除外。負担1の種目は重量80% |
| 強い | 安静時も痛む | その関節に負担が1以上の種目をすべて除外。医療機関の受診を促す表示を出す |

- 痛みの記録はセッション開始時に「まだ痛むか」を確認し、続ける／強さを変える／解除するを選んでもらう
- 解除後の初回は、その関節に関わる種目を重量90%から再開する
- セッション中に「痛む」ボタンでその場で種目を差し替えられる
- アプリは医療的な判断をしない。表示文言も「負担を避けるための調整」に留める

## 記録・タイマー・グラフ

ジムで片手で操作できることを最優先にし、1セットの記録は「提案値のままなら1タップ」で完了できるようにする。

画面構成：

1. 今日：今日のメニュー、持ち時間の入力、痛みの確認、開始ボタン
2. セッション：種目ごとのセット入力、インターバルタイマー、差し替え、メモ
3. 履歴：過去のセッション一覧と編集・削除
4. グラフ：推定1RM、部位別週セット数、体重・体脂肪率
5. 設定：モード、週の曜日、器具、種目マスタ、お気に入り・除外、各種数値、データの書き出し・読み込み

セットの記録項目：重量（kg）・回数・RIR（任意）・ウォームアップか本番か。前回の実績と今回の提案を並べて表示する。

インターバルタイマー：

- セット完了で自動開始。初期値はモードと種目タイプの休憩時間、±30秒ボタンで調整
- 終了時は音で知らせる（iOSのSafariはバイブレーション非対応のため）
- 画面を閉じて戻っても正しい残り時間を表示する（開始時刻を保存して差分で計算）

体重・体脂肪率：日付ごとに手入力。グラフには生の値と 7日移動平均を重ねて表示する。

メモ・体調：セッションごとの自由メモ、疲労感（5段階・任意）、痛みの記録。

グラフ：

- 種目別：セッションごとの推定1RMの最大値（折れ線）
- 部位別：週ごとのセット数（棒グラフ）、目標範囲を帯で表示
- 体重・体脂肪率：折れ線

## 技術・データ要件

サーバーを持たない静的サイトとして作り、GitHub Pagesで公開する。ジムで電波がなくても動くよう、オフライン対応のPWAにする。

| 項目 | 採用案（初期値） |
| --- | --- |
| 言語・ビルド | TypeScript + Vite |
| UI | Preact（軽量。不要なら素のTSでも可） |
| 保存 | IndexedDB（Dexie.js） |
| グラフ | Chart.js |
| オフライン | Web App Manifest + Service Worker（vite-plugin-pwa） |
| テスト | Vitest（生成・重量提案・痛み・ブランクのロジックを純粋関数にして単体テスト） |
| デプロイ | GitHub Actions で main へのpush時に Pages へ公開 |

データモデル（IndexedDBのテーブル）：

| テーブル | 主な項目 |
| --- | --- |
| settings | mode, weekdays[], equipmentEnabled{}, dumbbellWeights[], smithBarWeight, modeParams{}, favorites[], exclusions[{target, type, until?}] |
| exercises | 種目マスタ（「利用環境と種目マスタ」の項目）。初回に exercises.json から取り込む |
| plans | 生成された週プラン：weekStart, days[{weekday, splitName, items[{exerciseId, sets, repMin, repMax, targetRir, restSec}]}] |
| sessions | date, planDayRef, timeBudgetMin, fatigue?, note, entries[{exerciseId, sets[{weight, reps, rir?, isWarmup}]}] |
| pains | joint, side, level(light/moderate/severe), startDate, endDate? |
| bodyMetrics | date, weightKg, bodyFatPct? |

非機能要件：

- iPhoneのSafariとホーム画面追加後の表示で動くこと。縦画面、片手で届く位置に主要ボタン、タップ領域44pt以上
- ダークモード対応、表示は日本語
- 通信なしでも全機能が動く（データは端末外に送らない）
- バックアップ：全データをJSONで書き出し・読み込み。前回の書き出しから14日経ったら促す表示を出す（Safariは未使用のサイトのデータを削除することがあるため。ホーム画面に追加すれば影響を受けにくい）
- 書き出しJSONには `schemaVersion` を持たせ、将来の形式変更でも読み込めるようにする

Claude Codeへの実装方針：

- ロジック（`src/logic/`）とUI（`src/ui/`）を分け、ロジックは日付も引数で受け取る純粋関数にする
- 本書の表にある数値はすべて `src/config/defaults.ts` に定数としてまとめる
- 各判定表（重量提案、ブランク復帰、痛み）の行ごとにテストケースを1つ以上書く
- `vite.config` の `base` はリポジトリ名に合わせる（Pagesのサブパス公開のため）

## 開発の進め方と未決事項

Phase 1 で「生成→記録→次回提案」が一周回る状態を作り、実際にジムで使ってから残りを足す。

| フェーズ | 内容 | 完了条件 |
| --- | --- | --- |
| Phase 1 | 種目マスタ、設定、メニュー生成、セッション記録、タイマー、重量提案、お気に入り・除外、JSON書き出し・読み込み、Pages公開 | iPhoneのホーム画面から起動し、オフラインで1回分のトレーニングを記録でき、次回の提案が判定表どおりに出る |
| Phase 2 | 痛みによる回避、ブランク復帰、デロード提案、日ごとの持ち時間による削減 | 各判定表の全行がテストで通る |
| Phase 3 | グラフ、体重・体脂肪率、メモ・体調、バックアップの催促 | 3種のグラフが実データで表示される |
